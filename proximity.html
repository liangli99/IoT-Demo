🛠️ Step 1: How to Setup BLE on this Demo Board

Step-by-step physical hardware preparation, antenna layout guidelines, and FreeRTOS dual-core task allocation for the ESP32-WROOM-32 and Nordic nRF52840 boards adopted in the IoT demo.

1. Hardware & Power Setup Physical
  • Target MCU: ESP32-WROOM-32D (Tensilica Xtensa Dual-Core 240MHz).
  • Power Supply: Dedicated 3.3V LDO regulator (AP2112K rated for 600mA). The BLE radio draws up to 68mA peak current during advertising bursts.
  • Decoupling Capacitors: Place one 10µF tantalum and one 100nF ceramic capacitor within 3mm of the VDD33 pin to suppress ripple.
  • GPIO Assignments:
    • GPIO 21 / 22: I²C SDA/SCL (BME280 sensor)
    • GPIO 18: PWM output for 5V cooling fan (via 2N2222 NPN)
    • GPIO 19: Relay driver signal (optocoupled active LOW)
2. RF & Antenna Clearance RF Layout
  • PCB Antenna Keep-Out: The ESP32 meandered inverted-F antenna (MIFA) requires a minimum 15mm clearance free of copper planes, traces, or metal screws.
  • Enclosure Material: Use ABS, polycarbonate, or PLA enclosures. Never house the node in an unvented aluminum case, which introduces 25–40 dB attenuation.
  • Channel Coexistence: BLE primary advertising occurs on Channels 37 (2402 MHz), 38 (2426 MHz), and 39 (2480 MHz), intentionally slotted between standard 20MHz Wi-Fi channels (1, 6, 11) to avoid packet collision.
3. NimBLE Stack Selection Memory Saving
  • NimBLE vs Bluedroid: This demo deploys the Apache NimBLE stack instead of legacy Bluedroid.
    • Flash footprint: ~300KB (vs 850KB Bluedroid).
    • RAM usage: ~28KB (saves >100KB for application queues).
  • Dual-Core Pinning:
    • Core 0 (PRO_CPU): Dedicated to the NimBLE host task and Bluetooth controller baseband ISR.
    • Core 1 (APP_CPU): Dedicated to FreeRTOS sensor sampling and actuation loops.
ESP-IDF v5.2 Project Configuration (`sdkconfig.defaults`)

// Auto-generated NimBLE Advertising & GAP Configuration void configure_ble_advertising(void) { struct ble_gap_adv_params adv_params; struct ble_hs_adv_fields fields; memset(&fields, 0, sizeof(fields)); // Set Device Name fields.name = (uint8_t*)"ESP32-NODE-01"; fields.name_len = 13; fields.name_is_complete = 1; // Set Flags: LE General Discoverable + BR/EDR Unsupported fields.flags = BLE_HS_ADV_F_DISC_GEN | BLE_HS_ADV_F_BREDR_UNSUP; // Service UUID: 0x181A (Environmental Sensing) ble_uuid16_t env_uuid = BLE_UUID16_INIT(0x181A); fields.uuids16 = &env_uuid; fields.num_uuids16 = 1; fields.uuids16_is_complete = 1; ble_gap_adv_set_fields(&fields); // Advertising Timing Configuration memset(&adv_params, 0, sizeof(adv_params)); adv_params.conn_mode = BLE_GAP_CONN_MODE_UND; // Connectable undirected adv_params.disc_mode = BLE_GAP_DISC_MODE_GEN; adv_params.itvl_min = BLE_GAP_ADV_ITVL_MS(1000); adv_params.itvl_max = BLE_GAP_ADV_ITVL_MS(1020); // Set TX Power esp_ble_tx_power_set(ESP_BLE_PWR_TYPE_ADV, ESP_PWR_LVL_P3); ble_gap_adv_start(BLE_OWN_ADDR_PUBLIC, NULL, BLE_HS_FOREVER, &adv_params, ble_gap_event, NULL); }

📱 Step 4: How to Access Demo Board BLE via Mobile & Web

Access the physical demo board directly from smartphones and tablets. Use industry diagnostic apps like nRF Connect for Mobile or the integrated Mobile App.

Mobile Smartphone Diagnostic Apps nRF Connect / LightBlue
  • Step 1: Download nRF Connect: Install nRF Connect for Mobile (iOS / Android) by Nordic Semiconductor.
  • Step 2: Scan for Peripheral: Tap SCAN. Filter by RSSI > -80 dBm. Locate the advertisement name: ESP32-NODE-01.
  • Step 3: Connect & Discover: Tap CONNECT. The app negotiates MTU 247 and lists all GATT services.
  • Step 4: Interrogate Services:
    • Expand 0x181A Environmental Sensing: tap the multiple-down-arrow icon to enable live temperature and humidity notifications.
    • Expand 0xFF00 Actuation Service: tap the up-arrow icon on 0xFF01, enter UINT8 value (e.g. 80), and tap SEND to trigger the physical cooling fan!

🔒 BLE 5.0 Security & Pairing Specification

Industrial wireless links are susceptible to eavesdropping and man-in-the-middle (MITM) injection. Below are the cryptographic protections deployed in the IoT system.

LE Secure Connections ECDH P-256

Replaces legacy PIN/TK pairing with Elliptic Curve Diffie-Hellman (ECDH) P-256 key exchange. Eavesdroppers recording on-air packets cannot deduce the Long Term Key (LTK).

AES-128 CCM Encryption FIPS Validated

All GATT notifications and reverse write commands are encrypted using hardware AES-128 in Counter with CBC-MAC (CCM) mode, guaranteeing confidentiality and message integrity.

Resolvable Private Address Privacy

Sensor nodes rotate random MAC addresses every 15 minutes using an Identity Resolving Key (IRK). Only the authorized edge gateway can resolve the persistent device identity.
