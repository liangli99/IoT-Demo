TIER 5 PRESENTATION & ACTUATION LAYER

Native Mobile Client Architecture

The Mobile Application forms Tier 5 of the end-to-end IoT reference architecture. It serves as the primary human-machine interface (HMI), enabling operational monitoring of field nodes, real-time streaming visualization, and closed-loop actuation down to physical hardware.

📊
Real-Time Ingestion
Sub-50ms WebSocket Stream

Direct MQTT over WebSocket connection to AWS IoT Core with SigV4 authentication. Streams live telemetry from ESP32 BLE sensor nodes via Raspberry Pi 4 gateway without polling delay.

⚡
Reverse Actuation
Bidirectional Command Channel

Dispatches actuation command frames (e.g. solid-state relay toggles, fan PWM duty cycles, RTC sleep interval adjustments) down to constrained field hardware with acknowledgment receipts.

🛡️
Zero-Credential Client
Cognito Identity Pool & STS

Eliminates hardcoded AWS access keys. Uses Amazon Cognito Identity Pools to exchange temporary OpenID tokens for short-lived AWS STS credentials with strict scoped least-privilege IAM policies.

DATA PIPELINE DESIGN

Dual-Path Mobile Data Architecture

Production IoT client applications cannot rely exclusively on a single transport mechanism. The mobile client implements a robust Dual-Path Ingestion Pipeline: a real-time reactive streaming path for live telemetry and actuation, and an on-demand historical query path for time-series charts and deep auditing.

⚡
Path A: Real-Time Streaming (MQTT over WSS)
AWS IoT Core Message Broker • Port 443

Mechanism: Persistent TLS WebSocket connection using Paho MQTT with AWS SigV4 signed headers.

  • Topic Subscription: iot/telemetry/+ (wildcard across all provisioned sensor nodes).
  • Actuation Channel: iot/commands/{node_id} with QoS 1 (At least once delivery).
  • Payload Overhead: Minimal (~140 bytes JSON frame per telemetry packet).
  • Typical Latency: 25–45 ms roundtrip from cloud broker to mobile screen.
📜
Path B: Historical Query (REST via API Gateway)
Amazon DynamoDB Time-Series Persistence

Mechanism: HTTPS REST calls consumed via Retrofit2 and OkHttp with connection pooling.

  • Endpoint: GET /telemetry/{node_id}?start={ts}&end={ts}&limit=100
  • Backing Store: DynamoDB SensorTelemetry table (Partition key: device_id, Sort key: timestamp).
  • Client Cache: Room Database on Android provides instant offline launch capabilities.
  • Use Case: 24-hour historical trends, anomaly post-mortems, battery degradation curves.
🔄
Failover & Offline Reconnect Strategy
Exponential Backoff & Optimistic UI Reconciliation

When the mobile device enters cellular dead-zones or toggles airplane mode, the mobile app automatically falls back to the local SQLite/Room cache for chart rendering while queuing pending actuation requests. Upon network restoration, an Exponential Backoff Reconnect Algorithm (initial: 1s, max: 32s, jitter: ±20%) restores the WebSocket session and resynchronizes miss-window telemetry via REST.

SECURITY & IDENTITY LAYER

Client Security & Amazon Cognito Authentication

Constrained field devices rely on hardware-level X.509 client certificates and mutual TLS (mTLS) on port 8883. Mobile applications, however, are distributed to end-user devices where private keys cannot be securely pre-baked. The Mobile tier therefore utilizes Amazon Cognito Federated Identities with temporary AWS STS credentials.

🔐
Cognito Identity Pool Authentication Flow
OpenID Connect + AWS Security Token Service (STS)
  1. App Initialization: Client presents unauthenticated or Cognito User Pool JWT token to cognito-identity.us-east-1.amazonaws.com.
  2. STS Exchange: Cognito assigns a unique IdentityId and calls AssumeRoleWithWebIdentity.
  3. Temporary Credentials: AWS STS returns an AccessKeyId, SecretAccessKey, and SessionToken (valid for 60 minutes).
  4. SigV4 Signed WebSocket: The mobile MQTT client uses these credentials to compute an AWS Signature Version 4 HMAC-SHA256 signature for the WebSocket handshake query parameters.

ENGINEERING METHODOLOGY

Mobile App Design Procedure: Phases 1 through 6

Following modern software engineering practices, building a mission-critical IoT mobile application follows a structured six-phase engineering cycle from requirements definition to hardware-in-the-loop verification.

1
Phase 1 • Requirements & User Experience Specification

Telemetry Taxonomy & UX Information Architecture

Discovery

Define the physical metrics requiring visualization (temperature, relative humidity, barometric pressure, multi-axis kinetic acceleration, and DC battery level) and identify reverse control operations (compressor SSR relay, fan PWM, and diagnostic LED modes).

  • Create low-fidelity wireframes in Figma separating High-Level Fleet Monitoring from Node-Specific Diagnostics.
  • Establish UX safety constraints: require confirmation modals or optimistic state spinners for high-voltage actuator toggles.
  • Define latency budgets: Sub-100ms UI feedback for actuation; sub-200ms end-to-end telemetry refresh.
2
Phase 2 • Tech Stack Selection & Architectural Pattern

Clean Architecture with Jetpack Compose & MVI

Architecture

Standardize on modern native Android development using Kotlin 1.9+ and Jetpack Compose declarative UI. Enforce Clean Architecture with unidirectional data flow (Model-View-Intent / ViewModel StateFlow).

  • Presentation Layer: Declarative Composable functions reacting exclusively to immutable UiState objects.
  • Domain Layer: UseCases (e.g. ObserveTelemetryUseCase, DispatchActuatorCommandUseCase).
  • Data Layer: Repository pattern encapsulating AWS IoT MQTT WebSocket, Retrofit REST, and local Room SQLite cache.
3
Phase 3 • Network Layer & Cloud Ingestion Plumbing

AWS IoT WebSocket Client & SigV4 Authentication

Integration

Integrate the networking stack: Eclipse Paho MQTT client configured to tunnel over secure WebSockets on port 443, authenticated via Amazon Cognito Identity Pools.

  • Implement AWS SigV4 signer to authenticate the WebSocket upgrade request without embedding static secrets.
  • Configure MQTT Keep-Alive interval (60 seconds) and set up an automatic reconnect loop with exponential backoff.
  • Establish background Coroutine scopes with Dispatchers.IO to prevent blocking the Android main rendering thread.
4
Phase 4 • High-Performance Reactive Visualization

Custom SVG Gauges & Low-Allocation Sparklines

UI Engine

Construct hardware-accelerated UI components capable of rendering incoming telemetry packets without triggering frequent garbage collection (GC) pauses.

  • Design a dynamic circular radial gauge with smooth color gradient interpolation: Green (<24°C) → Cyan (24–26°C) → Amber (26–30°C) → Rose (>30°C).
  • Implement lightweight Android Canvas sparklines maintaining a fixed ring buffer (30 points) with Zero Object Allocations in the draw loop.
  • Create animated status pills indicating node heartbeat and BLE connection health.
5
Phase 5 • Reverse Control & Smart Hysteresis Logic

Actuation Safety, Acknowledgment & AC Automation

Control

Implement the closed-loop control system. Both manual override toggles and automated thermostat engines are supported.

  • Program dual-threshold hysteresis cooling: AC turns ON at ≥26.0°C and turns OFF at ≤24.0°C to prevent rapid relay contact chatter.
  • Implement optimistic UI toggle states: switch animates immediately, but displays a pulsing sync indicator until receipt of hardware acknowledgment.
  • Add fail-safe timeout: if no ACK returns within 3.5 seconds, roll back UI state and trigger an alert toast.
6
Phase 6 • Testing, Profiling & Edge-Case Validation

Hardware-in-the-Loop & Battery Consumption Profiling

Verification

Subject the mobile app to rigorous verification under simulated network degradation, rapid telemetry burst rates, and battery constraint testing.

  • Verify CPU and memory footprint using Android Studio Profiler (target: <5% CPU utilization, zero memory leaks).
  • Conduct battery drain benchmarks with Android Battery Historian to ensure WebSocket keep-alive wake-locks do not prevent CPU deep-sleep.
  • Verify failover when turning off gateway Wi-Fi: app logs offline state, buffers control intents, and restores telemetry upon reconnect.
REACTIVE STATE PATTERN

MVI Architecture & Jetpack Compose StateFlow

To eliminate synchronization bugs and race conditions across multiple asynchronous telemetry streams, the mobile client adopts the Model-View-Intent (MVI) pattern with Kotlin coroutines and StateFlow.

🔄
Unidirectional Data Flow (UDF) Loop
Deterministic State Mutation
  1. User Intent: User interacts with the UI (e.g. toggles AC mode, switches active sensor node, changes threshold).
  2. ViewModel Action: ViewModel receives the intent and executes the corresponding domain use case.
  3. Repository Dispatch: Repository broadcasts MQTT command to AWS IoT Core or queries DynamoDB REST endpoint.
  4. Immutable State Emission: ViewModel reduces new data into a single immutable TelemetryUiState emitted via StateFlow.
  5. Compose Recomposition: Only the specific Composable UI nodes observing the mutated properties re-render.

CLOSED-LOOP CONTROL

Reverse Actuation & Hysteresis Cooling Loop

IoT architectures are defined by their capacity not only to sense, but to actuate. The mobile client incorporates an intelligent autonomous cooling supervisor coupled with manual override authority.

❄️
Dual-Threshold Hysteresis
Preventing Relay Rapid Cycling

Single-threshold controls suffer from high-frequency relay bouncing when temperature hovers at the boundary. Hysteresis establishes an Upper Setpoint (26.0°C) where the cooling compressor engages, and a Lower Setpoint (24.0°C) where it disengages, preserving SSR relay contact lifespan.

⚡
Optimistic UI & Rollback
Graceful Failure Handling

Upon user toggle, the mobile switch animates immediately with an active sync spinner. If network delivery fails or the ESP32 node fails to publish an acknowledgment within 3.5 seconds, the switch automatically rolls back to its prior state with an audio alert and error toast.

🚨
Cloud Rule Coordination
AWS Lambda + Mobile Push

Independent of the mobile app, AWS IoT Core SQL rules evaluate every telemetry packet in real time. If temperature exceeds 30.0°C, a Lambda function executes simultaneously to trigger an Amazon SNS push notification directly to the mobile device.

@Composable
fun RadialGaugeCanvas(temperature: Float) {
    val sweepAngle = ((temperature.coerceIn(15f, 40f) - 15f) / 25f) * 240f
    Canvas(modifier = Modifier.size(180.dp, 100.dp)) {
        // Track
        drawArc(
            color = Color(0xFF1E293B),
            startAngle = 150f,
            sweepAngle = 240f,
            useCenter = false,
            style = Stroke(width = 12.dp.toPx(), cap = StrokeCap.Round)
        )
        // Active Fill
        drawArc(
            color = getTempColor(temperature),
            startAngle = 150f,
            sweepAngle = sweepAngle,
            useCenter = false,
            style = Stroke(width = 12.dp.toPx(), cap = StrokeCap.Round)
        )
    }
}

fun SparklineCanvas(points: List<Float>) {
    if (points.size < 2) return
    Canvas(modifier = Modifier.fillMaxWidth().height(50.dp)) {
        val min = points.minOrNull() ?: 15f
        val max = points.maxOrNull() ?: 35f
        val range = if (max == min) 1f else (max - min)
        val stepX = size.width / (points.size - 1)

        val path = Path()
        points.forEachIndexed { index, temp ->
            val x = index * stepX
            val y = size.height - (((temp - min) / range) * size.height)
            if (index == 0) path.moveTo(x, y) else path.lineTo(x, y)
        }
        drawPath(path = path, color = Color(0xFF00D4FF), style = Stroke(width = 2.dp.toPx()))
    }
}

fun getTempColor(temp: Float): Color = when {
    temp > 30f -> Color(0xFFF43F5E)
    temp > 26f -> Color(0xFFF59E0B)
    temp > 24f -> Color(0xFF00D4FF)
    else -> Color(0xFF10B981)
}

data class TelemetryUiState(
    val activeNodeId: String = "sensor_node_01",
    val isConnected: Boolean = false,
    val currentTemp: Float = 24.5f,
    val currentHumidity: Float = 55.0f,
    val currentPressure: Float = 1013.25f,
    val currentVibration: Float = 0.025f,
    val currentBattery: Int = 92,
    val isAcOn: Boolean = false,
    val isAutoMode: Boolean = true,
    val sparklineHistory: List<Float> = listOf(24.2f, 24.5f, 24.8f, 25.1f)
)

class IoTViewModel(
    private val mqttClient: AwsIotMqttClient = AwsIotMqttClient()
) : ViewModel() {

    private val _uiState = MutableStateFlow(TelemetryUiState())
    val uiState: StateFlow<TelemetryUiState> = _uiState.asStateFlow()

    fun connectToCloud() {
        viewModelScope.launch {
            mqttClient.connect(
                endpoint = "a1xxxxxxxxxxx-ats.iot.us-east-1.amazonaws.com",
                cognitoIdentityPoolId = "us-east-1:12345678-abcd-ef01-2345-6789abcdef01",
                onConnected = {
                    _uiState.update { it.copy(isConnected = true) }
                    subscribeToNodeTelemetry(_uiState.value.activeNodeId)
                },
                onDisconnected = {
                    _uiState.update { it.copy(isConnected = false) }
                },
                onMessageReceived = { topic, record ->
                    handleIncomingTelemetry(record)
                }
            )
        }
    }

    private fun subscribeToNodeTelemetry(nodeId: String) {
        mqttClient.subscribe("iot/telemetry/$nodeId")
    }

    private fun handleIncomingTelemetry(record: TelemetryRecord) {
        if (record.deviceId != _uiState.value.activeNodeId) return

        val updatedHistory = (_uiState.value.sparklineHistory + record.temp).takeLast(30)
        
        // Hysteresis Evaluation in Auto Mode
        var acState = _uiState.value.isAcOn
        if (_uiState.value.isAutoMode) {
            if (record.temp >= 26.0f && !acState) {
                acState = true
                dispatchActuationCommand(true)
            } else if (record.temp <= 24.0f && acState) {
                acState = false
                dispatchActuationCommand(false)
            }
        }

        _uiState.update {
            it.copy(
                currentTemp = record.temp,
                currentHumidity = record.humidity,
                currentPressure = record.pressure,
                currentVibration = record.vibration,
                currentBattery = record.battery,
                isAcOn = acState,
                sparklineHistory = updatedHistory
            )
        }
    }

    fun selectNode(nodeId: String) {
        _uiState.update { it.copy(activeNodeId = nodeId) }
        subscribeToNodeTelemetry(nodeId)
    }

    fun toggleAcRelay(turnOn: Boolean) {
        _uiState.update { it.copy(isAcOn = turnOn, isAutoMode = false) }
        dispatchActuationCommand(turnOn)
    }

    private fun dispatchActuationCommand(relayState: Boolean) {
        val cmdTopic = "iot/commands/${_uiState.value.activeNodeId}"
        val payload = """
            {
                "command_id": "cmd-${System.currentTimeMillis()}",
                "device_id": "${_uiState.value.activeNodeId}",
                "action": "SET_ACTUATOR",
                "params": { "relay": $relayState }
            }
        """.trimIndent()
        mqttClient.publish(cmdTopic, payload)
    }

    fun disconnectFromCloud() {
        mqttClient.disconnect()
    }
}

class AwsIotMqttClient {

    private var client: MqttAsyncClient? = null

    fun connect(
        endpoint: String,
        cognitoIdentityPoolId: String,
        onConnected: () -> Unit,
        onDisconnected: () -> Unit,
        onMessageReceived: (String, TelemetryRecord) -> Unit
    ) {
        val clientId = "MobileApp_${System.currentTimeMillis()}"
        val brokerUrl = "wss://$endpoint:443/mqtt"

        client = MqttAsyncClient(brokerUrl, clientId, MemoryPersistence())
        val options = MqttConnectOptions().apply {
            isCleanSession = true
            keepAliveInterval = 60
            isAutomaticReconnect = true
        }

        client?.connect(options, null, object : IMqttActionListener {
            override fun onSuccess(asyncActionToken: IMqttToken?) {
                onConnected()
            }

            override fun onFailure(asyncActionToken: IMqttToken?, exception: Throwable?) {
                onDisconnected()
            }
        })

        client?.setCallback(object : MqttCallbackExtended {
            override fun connectComplete(reconnect: Boolean, serverURI: String?) {
                onConnected()
            }

            override fun connectionLost(cause: Throwable?) {
                onDisconnected()
            }

            override fun messageArrived(topic: String?, message: MqttMessage?) {
                val payload = String(message?.payload ?: ByteArray(0), StandardCharsets.UTF_8)
                val json = JSONObject(payload)
                val record = TelemetryRecord(
                    deviceId = json.optString("device_id", "unknown"),
                    temp = json.optDouble("temp", 0.0).toFloat(),
                    humidity = json.optDouble("humidity", 0.0).toFloat(),
                    pressure = json.optDouble("pressure", 1013.25).toFloat(),
                    vibration = json.optDouble("vibration", 0.0).toFloat(),
                    battery = json.optInt("battery", 100)
                )
                onMessageReceived(topic ?: "", record)
            }

            override fun deliveryComplete(token: IMqttDeliveryToken?) {}
        })
    }

    fun subscribe(topic: String) {
        client?.subscribe(topic, 1)
    }

    fun publish(topic: String, jsonPayload: String) {
        val message = MqttMessage(jsonPayload.toByteArray(StandardCharsets.UTF_8)).apply {
            qos = 1
        }
        client?.publish(topic, message)
    }

    fun disconnect() {
        try {
            client?.disconnect()
        } catch (_: Exception) {}
    }
}

import kotlinx.coroutines.*

class ActuatorControlManager(
    private val onSendMqttCommand: (String, String) -> Unit,
    private val onAckTimeout: (String) -> Unit
) {
    private val pendingAcks = mutableMapOf<String, Job>()
    private val scope = CoroutineScope(Dispatchers.Default + SupervisorJob())

    fun sendActuatorCommand(nodeId: String, relay: Boolean, fanPwm: Int) {
        val commandId = "cmd-${System.currentTimeMillis()}"
        val topic = "iot/commands/$nodeId"
        val payload = """
            {
                "command_id": "$commandId",
                "device_id": "$nodeId",
                "action": "SET_ACTUATOR",
                "params": {
                    "relay": $relay,
                    "fan_pwm": $fanPwm
                }
            }
        """.trimIndent()

        // 3.5 Second timeout watcher for optimistic UI safety
        val timeoutJob = scope.launch {
            delay(3500)
            if (pendingAcks.containsKey(commandId)) {
                pendingAcks.remove(commandId)
                onAckTimeout(commandId)
            }
        }
        pendingAcks[commandId] = timeoutJob

        onSendMqttCommand(topic, payload)
    }

    fun handleAckReceipt(commandId: String) {
        pendingAcks[commandId]?.cancel()
        pendingAcks.remove(commandId)
    }
}

1. Live Ingestion & WebSocket Streaming 25% Sub-50ms telemetry updates; zero frame drops; smooth radial gauge and animated sparkline. Telemetry displays but with noticeable jitter or periodic disconnections. Failure to establish WebSocket connection; relying exclusively on REST polling.
2. Reverse Actuation & Feedback Loop 25% Bilateral actuation; optimistic toggle update with acknowledgment receipts; fail-safe timeout handling. Actuation toggles hardware but lacks feedback loop or optimistic synchronization. Actuator commands fail to reach field devices or cause app crashes.
3. Security & Cognito Integration 20% Zero hardcoded secrets; Cognito Identity Pool STS credential exchange; scoped least-privilege IAM policy. Cognito authentication functional but policy is overly permissive (e.g. iot:*). AWS Access Key / Secret Key hardcoded in mobile application source code.
4. Clean Architecture & Code Quality 15% MVI / ViewModel StateFlow pattern; clean separation of UI, Domain, and Data layers; zero boilerplate memory leaks. Standard MVVM implemented but with monolithic activities or tightly coupled network calls. Spaghetti code with network operations performed directly on Android Main Thread.
5. Offline Resilience & Anomaly Response 15% Graceful exponential backoff reconnect; local Room database cache; immediate UI response to temperature anomalies. App reconnects after network loss but loses cached history or freezes temporarily. App crashes when network is disconnected or fails to recover upon restoration.
